# Chromatic

Chromatic 是一个基于 Compositor 的 AI 照片调色学习项目，目标是让 AI 分析照片、解释调色建议，并生成可以继续编辑的调整结果。项目同时用于学习如何构建 Agent。

## 本地运行指南：第一次使用从这里开始

下载本项目后，可以在自己的电脑上运行网页界面。**这不是在线服务，也不是双击 ZIP 就能启动的独立 App**：需要先安装下面的工具、配置自己的模型密钥，再启动本地网页。

当前仓库网页提供照片上传、可选参考作品、AI 分析、冷暖／饱和度／曝光／对比度四项基础调色和文字反馈。最近验证的九项原生色彩平衡与模型总曲线仍属于仓库外的独立实验，**尚未接入这里的网页，也不包含在当前下载包中**。

### 1. 使用前准备

| 项目 | 要求与用途 |
| --- | --- |
| 电脑 | 完整体验需要 **Apple 芯片 Mac、macOS 26 或更新版本**；这是当前 Compositor 官方的运行要求。Windows、Linux 和 Intel Mac 不在本项目完整流程的已验证范围内。 |
| Compositor | 用于打开调色工程、检查实际效果和导出图片。到 [Compositor 官方下载页](https://github.com/robbietilton/Compositor/releases)下载安装，将 `Compositor.app` 放入“应用程序”，路径应为 `/Applications/Compositor.app`，并先手动打开一次。安装官方成品 App 不需要自行编译或安装完整 Xcode。官方要求见 [Compositor README](https://github.com/robbietilton/Compositor#requirements)。本项目曾用 1.5.3、1.5.4 检查工程，不代表所有版本均已验证。 |
| uv | 管理 Python 版本、项目依赖和运行环境，下文有安装命令。不需要自己逐个安装 Python 包。 |
| 模型凭证与网络 | 准备自己的 [DeepSeek API Key](https://platform.deepseek.com/)，账号需具备调用权限及可用额度，电脑需能访问该服务。当前代码固定请求 `deepseek-flash`，模型可用性由服务方决定；这里尚未提供其他模型的界面切换。 |
| 照片 | 自备一张 JPEG/PNG 原照片，可再准备一张参考作品或截图。仓库不包含开发者的原照片、参考作品、历史结果或密钥。 |

### 2. 下载代码并进入项目文件夹（二选一）

**方式 A：下载 ZIP，适合未使用过 Git 的用户。**

1. 在 [项目主页](https://github.com/Leo-Nature/chromatic) 点击绿色 **Code → Download ZIP**，或使用 [main 分支 ZIP 下载链接](https://github.com/Leo-Nature/chromatic/archive/refs/heads/main.zip)。
2. 双击 ZIP 解压，进入包含 `app.py`、`pyproject.toml` 和 `uv.lock` 的文件夹；通常名为 `chromatic-main`。
3. 打开 macOS“终端”。如果解压到默认“下载”目录，执行：

```bash
cd ~/Downloads/chromatic-main
```

如果文件夹在别处，在终端输入 `cd `（最后有一个空格），把解压后的文件夹拖进终端，再按回车。`cd` 的作用是切换到项目目录。下面的项目命令都在这个目录执行。

**方式 B：已经安装 Git，可在终端下载。**

```bash
git clone https://github.com/Leo-Nature/chromatic.git
cd chromatic
```

`git clone` 会下载代码与版本历史；ZIP 是当前代码快照，两种方式都能运行项目。若提示没有 Git，可直接选 ZIP，无需先解决 Git 安装。

### 3. 安装 uv（已有则跳过安装）

根据 [uv 官方安装说明](https://docs.astral.sh/uv/getting-started/installation/)，在终端执行：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

安装后关闭并重新打开终端，按第 2 步重新进入项目目录，再检查：

```bash
uv --version
```

能显示版本号即可。如果仍提示 `command not found: uv`，查看安装器给出的路径提示，或查阅上面的官方安装说明；不要继续执行后面的启动命令。

### 4. 安装项目依赖

确认当前文件夹能看到 `pyproject.toml` 和 `uv.lock`，执行：

```bash
uv sync --locked
```

uv 会在项目内创建独立的 `.venv` 环境，按 `uv.lock` 安装依赖；项目的 `.python-version` 指定 Python 3.11，缺少合适解释器时 uv 可自动下载。首次安装需要联网。`--locked` 要求使用随仓库提供的锁文件，不在安装时随意更新版本。通常不需要手动激活 `.venv`。

### 5. 配置自己的 DeepSeek 密钥

在项目目录执行以下命令，创建并用 macOS 文本编辑打开本地配置文件；`touch` 不会清空已有文件：

```bash
touch .env
open -e .env
```

在 `.env` 中添加下面这一行，把占位文字替换为自己的完整 API Key，然后保存为纯文本：

```dotenv
DEEPSEEK_API_KEY=replace_with_your_own_deepseek_api_key
```

文件名必须是 `.env`，不是 `.env.txt`，位置与 `app.py` 相同。它是隐藏文件，在 Finder 可按 `Command + Shift + .` 显示隐藏文件。已有配置请保留，只添加或更新这一项。程序也支持同名环境变量，已设置的环境变量优先于 `.env`。

密钥由使用者自行配置，不随项目提供，也不要提交到 GitHub。仓库已忽略 `.env`。点击实际分析或反馈提交时，会向 DeepSeek 发送相应照片预览和文字，并产生 API 用量；只打开网页不调用模型。

### 6. 启动本地网页

在项目目录执行：

```bash
uv run --locked streamlit run app.py --server.address 127.0.0.1 --server.port 8501 --server.headless true --browser.gatherUsageStats false
```

保持终端窗口运行，在浏览器手动打开 **<http://127.0.0.1:8501>**。网页只监听本机；这个地址不能直接发给别人访问。看到 Chromatic 标题和“新建调色”入口，表示本地界面已启动，但还没有验证模型调用或最终调色效果。

停止时回到终端按 **Control + C**。下次使用只需进入项目目录，再执行这条启动命令，通常无需重新安装依赖或重新填写密钥。

### 7. 第一次完整使用

1. 展开“新建调色”，选择“上传原照片”，上传自己的 JPEG/PNG。首次运行没有历史记录是正常现象，不需要寻找开发者的 `test.jpg` 或填写其本地工程路径。
2. 可选上传参考作品或截图，填写修图要求。
3. 点击“检查输入并预览”，确认照片正确。这一步不调用模型。
4. 点击“开始分析并调色”，等待页面显示分析、四项参数和新结果记录。
5. 点击“在 Compositor 中打开”，在本机软件内查看实际调色效果。结果是可编辑的 `.comp` 工程，**不是已经导出的 PNG**；输入预览也不是调色后的成片。
6. 如需带走图片，在 Compositor 内手动导出 PNG，另存到自己选择的位置。当前网页不自动渲染／导出；“下载原尺寸 PNG”只用于已登记且匹配当前版本的成片，首次运行或新版本没有该按钮并不代表调色失败，手动导出的文件也不会自动登记回网页。
7. 如需继续调整，在网页选中相应版本，填写反馈，先检查再明确提交；新版本仍从同一原工程生成，原照片保留。

原照片上限为 50 MiB、8000 万像素；参考图上限为 20 MiB。使用普通不透明、单帧 JPEG/PNG，暂不支持直接上传 RAW、多帧或带透明像素的图片。上传材料、分析与新工程会保存到本机项目的 `outputs/`，运行时按需创建，不会因为使用网页而自动上传到 GitHub。

### 8. 常见问题

| 情况 | 处理方法 |
| --- | --- |
| 找不到 `pyproject.toml` 或 `app.py` | 终端所在目录不对。重新执行第 2 步的 `cd`，进入解压后包含这些文件的目录。 |
| 缺少 `DEEPSEEK_API_KEY` | 检查 `.env` 的名称、位置和变量名；不要保留占位文字。若返回认证、额度或模型不可用错误，核对自己的服务账号与模型权限。 |
| 浏览器无法连接 | 确认终端中的服务仍在运行。若提示 8501 端口占用，可把启动命令中的端口改成 `8502`，浏览器也改用 `http://127.0.0.1:8502`。 |
| “在 Compositor 中打开”失败 | 确认使用受支持的 Mac，且已将软件安装到 `/Applications/Compositor.app`。按钮在运行本项目的电脑上打开工程；新安装用户可先手动启动 Compositor 检查安装。 |
| 参数存在，但画布效果与导出不一致 | 开发机曾在部分工程和绘制条件下遇到此现象。可按下面的可选办法尝试 CPU 画布；这是本机绘制绕行方式，不是通用修复或必需安装步骤。 |
| 安装依赖或模型连接失败 | 查看终端／页面的实际错误，检查网络及自己配置的代理；本项目不会自动提供模型服务或绕过网络限制。 |

**可选：CPU 画布绕行。** 先保存自己的工程并正常退出 Compositor，再执行：

```bash
defaults write com.wonderassembly.compositor CompositorCPUCanvas -bool true
```

重新打开 Compositor 后生效。该设置在开发机的独立对照中改善了显示一致性，但可能影响大图操作速度；本项目不会自动替下载者修改应用设置。若原先没有设置此键，恢复默认时先保存并退出软件，再执行以下命令并重新启动：

```bash
defaults delete com.wonderassembly.compositor CompositorCPUCanvas
```

如果此前已有自己的设置，请恢复此前的值，而不是直接删除。此开关只影响本机 Compositor，不随 GitHub 下载传播。

## 功能目标与验收标准

### 自动初步调色（目标，尚未完成）

输入一张照片和修图要求，AI 分析曝光、白平衡、对比度及色彩，提出调整方案，由程序校验后应用到 Compositor 工程副本。

验收标准：程序输出调色建议和理由，并生成能在 Compositor 中打开的调整后工程；用户开关调整图层，能够检查前后变化，原始照片和工程得到保留。

### 参考作品调色（完整目标尚未完成）

输入原照片、已调色的参考作品和修图要求，AI 分析两张图片的差异，借鉴参考作品的冷暖、对比度、饱和度及阴影和高光色彩关系，制定适合原照片的调整方案。

第一版计划在请求中同时提供两张图片，无需先训练专用模型。照片的光线和内容存在差异，参考风格调色不承诺完全复制参考图的观感。

验收标准：程序说明借鉴了哪些色彩特征，并生成可编辑的调整后工程；用户通过前后对比和参考图，判断结果是否朝目标风格靠近。

当前已支持双图分析、参考风格描述及迁移理由，并初步执行冷暖、饱和度、曝光和对比度；本次样片的四项组合效果已通过用户检查，不代表其他照片的审美效果或完整风格迁移均已验证。

## 预期工作流程

这是待逐步实现的流程：

```text
照片 + 修图要求 + 可选参考图
  → 模型分析并提出方案
  → Python 校验参数
  → 调色工具写入 Compositor 工程副本
  → 打开或渲染工程，查看结果
  → 用户反馈，必要时继续调整
```

模型负责理解和建议，工具负责执行调整，Python 程序负责连接各步骤、处理错误和保存结果。

## 输出目录规范（已通过用户验收）

目录规范由 `output_layout.py` 集中定义，网页新任务使用以下位置：

```text
outputs/
├── sources/                    独立原始工程与导入记录的分类位置
├── inputs/
│   ├── initial/<任务ID>/       初次任务的上传材料、预览和确认记录
│   └── feedback/<任务ID>/      反馈确认记录
├── runs/
│   ├── ui-run-<时间>-<任务ID>/        初次调色结果
│   └── ui-feedback-<时间>-<任务ID>/   反馈结果
├── experiments/                早期实验的分类位置
└── checks/
    └── migration-previews/     本步骤的迁移预演与验证记录
```

路径函数只返回位置，不预先创建全部目录。网页实际准备任务时才创建对应的输入目录，提交流程创建新结果目录。上传照片生成的 `source.comp` 和 `source.import.json` 继续跟该次上传材料一起保存在 `inputs/initial/<任务ID>/`，保证来源材料集中；`sources/` 用于独立原始工程，不复制上传任务的工程。独立命令行工具仍尊重明确填写的 `--output`，本步骤没有自动重写用户指定路径。

历史文件已经按分类迁移，网页新任务继续使用同一套规则。页面仍兼容旧根目录与旧任务，并查找 `runs/<任务>/`、`experiments/` 和 `experiments/<实验>/` 中的报告，不递归扫描图片资源、输入材料与检查记录。当前默认原工程位于 `outputs/sources/test-photo-source.comp`；如果另一个本地副本仍使用旧布局，路径函数也支持回退。

下文历史步骤中的叙述保留当时路径；命令示例与本次成片入口已更新。查找旧文件时，可在外部备份目录的 `MIGRATION.md` 和 `journal.json` 中对照原位置与新位置。浏览器中尚未提交的旧确认可能仍保留旧路径，迁移后应重新打开页面并重新检查输入或反馈，不自动重放提交。

## 基础对比度执行

独立工具新增可选 `--contrast`，建议值范围为 `[-1, 1]`，不是百分比。省略时不新增或修改对比度层；显式 `0` 时创建或重置为中性曲线。旧的冷暖、饱和度和曝光调用继续兼容。

```bash

```

参数结构与插值方式依据固定版本的 [Compositor Curves.swift](https://github.com/robbietilton/Compositor/blob/365b5745eda537f984f3d5bed1e53c361dbc9c91/Compositor/Document/Curves.swift)：`curves.channel` 为 `RGB`，`channels` 依次是 RGB 总曲线、红、绿、蓝。每条曲线需有 2～32 个点，起止横坐标为 0 和 255，横坐标严格递增，横纵坐标均为有限数值且在 `[0, 255]` 内；允许小数。编辑器以保形三次 Hermite 插值平滑连接控制点，避免过冲。像素先经过单独颜色通道曲线，再经过 RGB 总曲线。

本项目只调整总曲线，单独红、绿、蓝保持中性。暂定幅度 `a = contrast_adjustment * 32`，不取整；总曲线的五个点为：

```text
(0, 0), (64, 64-a), (128, 128), (192, 192+a), (255, 255)
```

正值压低暗部控制点并抬高亮部，负值反向；黑、白及中间控制点固定。零值为中性直线。全范围内控制点纵坐标也严格递增。这是有边界的基础 S 曲线方案，未完成样片校准；`0.15` 不代表视觉对比度增加 15%。RGB 总曲线逐通道处理仍可能改变颜色观感，也不代表感知亮度保持不变。保留纯黑与纯白，因此降低对比度不会把纯黑抬成灰。
